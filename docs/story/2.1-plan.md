# Story 2.1 — 数据库与账号

## 主要目标

接入 PostgreSQL 和 Auth.js，提供注册、登录、角色和个人设置，作为所有用户数据的基础。

## 验收标准

- [ ] Drizzle ORM 管理数据库结构，迁移脚本可重复执行；本地用 Docker Compose 启动 PostgreSQL。
- [ ] 表：用户、账号（第三方）、会话、角色、用户设置（界面语言、每日目标、时区）。
- [ ] 登录方式：邮箱魔法链接、Google、GitHub。
- [ ] 角色：访客、用户、编辑、版主、管理员；提供服务端权限检查工具函数。
- [ ] 设置页：昵称、头像、界面语言、每日目标、时区。
- [ ] 数据导出（JSON）与账号删除（需二次确认），删除后个人数据清除。
- [ ] 登录接口限流。
- [ ] 环境变量通过 `.env.example` 说明，密钥不入库。

## 功能要点

- 时区用于计算“今天”，打卡和每日目标都依赖它。
- 访客的本地进度在注册后合并到账号。

## 单元测试用例设计

- 权限函数：用户访问管理员操作返回拒绝；管理员通过。
- 时区：UTC+8 用户在 UTC 15:59 和 16:01 分属不同的“今天”。
- 访客进度合并：本地有 2 课完成记录，合并后账号有对应记录且不重复。

## 行为测试用例设计

- 用测试邮箱完成魔法链接登录，进入设置页修改每日目标，刷新后保持。
- 删除账号后用相同邮箱重新登录，得到全新空账号。
